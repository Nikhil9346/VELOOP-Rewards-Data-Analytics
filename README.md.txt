# VELOOP Rewards – Data Analytics Project

## Project Overview

This project focuses on analyzing VELOOP Rewards data and understanding user activity, engagement, referrals, rewards, wallet transactions, and withdrawals.

The work includes data analysis, data quality checks, KPI definitions, event tracking requirements, dashboard planning, data modeling, and recommendations for future analytics implementation.

The analysis uses a simulated dataset and proposed analytics requirements. Some areas require further verification with the actual VELOOP product and engineering teams.

## Project Objectives

- Understand user registration and activity.
- Analyze onboarding and user engagement.
- Study referral performance.
- Review task, reward, and wallet analytics.
- Identify data quality issues and missing information.
- Define important business KPIs.
- Prepare dashboard requirements.
- Identify analytics gaps and recommend improvements.

## Key Findings

- The simulated dataset contains 1,000 users.
- 72 users have missing last-login information.
- 855 users have verified email addresses.
- 722 users have completed onboarding.
- User acquisition and engagement can be analyzed using the available data.
- Some analytics areas, such as rewards, wallets, withdrawals, and referrals, require additional data or verification.
- Clear event tracking and KPI definitions are important for reliable reporting.

## Recommendations

- Improve the collection of user activity data.
- Track important user actions through clearly defined events.
- Maintain consistent KPI definitions.
- Improve data quality checks.
- Collect complete reward, wallet, withdrawal, and referral data.
- Build dashboards to monitor user activity and business performance.
- Verify proposed analytics requirements with the VELOOP engineering and product teams before implementation.


## Limitations

- The dataset used in this project is simulated.
- Actual VELOOP production data was not available.
- Some business metrics could not be calculated due to missing data.
- Event tracking, pipeline, and dashboard designs are proposed, not confirmed implementations.
- Recommendations require validation with the actual VELOOP teams.
